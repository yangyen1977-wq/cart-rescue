## 測試焦點：Day 17 計畫落實

### 1. Bot 檢測風險評估

**背景**：Day 17 計畫第一項為測試 TravelPlus 是否對自動化瀏覽器有檢測機制。今日執行瀏覽器訪問與信號探測。

**測試結果**：

| 檢測項目 | TravelPlus 結果 | 風險評級 |
|---------|----------------|---------|
| `navigator.webdriver` | **True**（瀏覽器暴露）| ⚠️ 高 |
| User-Agent 含 "HeadlessChrome" | **是** | ⚠️ 高 |
| Cloudflare challenge page | 無（正常載入）| ✅ 低 |
| reCAPTCHA / hCaptcha | 無 | ✅ 低 |
| Akamai Bot Manager | 無明顯信號 | ✅ 低 |
| 頁面內容完整性 | 完整載入（639KB HTML）| ✅ 低 |
| 產品頁面可訪問 | 正常（304KB HTML）| ✅ 低 |

**結論**：
- **TravelPlus 未部署主動 Bot 阻擋機制**：頁面可正常載入、無驗證碼挑戰
- **但 `navigator.webdriver` 和 User-Agent 暴露**：這是 Playwright/Chrome headless 的默認行為
- **風險評估**：目前無風險，但若 TravelPlus 未來升級 Cloudflare Bot Fight Mode，CartRescue 可能被封鎖
- **建議**：生產環境應啟用 stealth 模式或手動覆蓋 User-Agent

### 2. 無瀏覽器價格提取測試（Browserless Price Extraction）

**背景**：Day 17 引用了 arXiv:2609.01030「Web Price Extraction: State of the Art and an Adaptive Browserless Implementation」。今日測試直接用 `curl` HTTP 請求提取 TravelPlus 價格，與瀏覽器自動化結果比對。

**測試方法**：
- 使用 `curl` + 正常 User-Agent 抓取首頁（639KB）與產品頁（304KB）
- 使用正規表達式提取價格資訊

**提取結果**：

| 來源 | 提取方式 | 成功？ | 精度 |
|------|---------|--------|------|
| 首頁 HTML | `curl` + regex | ✅ | 提取所有產品價格（NT$8080、NT$9080、NT$6400、NT$7280 等） |
| 產品頁 HTML | `curl` + regex | ✅ | 精確提取：定價 NT$13,800、特價 NT$8,080 |
| 折扣標示 | `curl` + regex | ✅ | 提取「約64折」「約8折」等標示 |

**正規表達式提取準確率**：
- 定價提取：`定價\s*NT\s*[:：]\s*(\d+)` → 成功提取全部定價
- 特價提取：`特價\s*NT\s*[:：]\s*(\d+)` → 成功提取全部特價
- 主產品組合價：`定價\s*NT\s*[:：]\s*\d+\s*\(\s*特價\s*[:：]\s*\d+\s*\)` → 成功提取「定價 NT : 13800 (特價 : 8080 )」

**與瀏覽器自動化比對**：

| 指標 | 無瀏覽器（curl） | 瀏覽器自動化 | 差異 |
|------|----------------|------------|------|
| 請求時間 | ~2 秒 | ~5-8 秒（含渲染）| curl 快 3-4 倍 |
| HTML 大小 | 完整 304KB | 相同 | 無差異 |
| 價格提取 | 正確 | 正確 | 無差異 |
| JavaScript 動態內容 | 無法取得 | 可取得 | 需評估影響 |
| 被阻擋風險 | 低（HTTP 請求）| 中等（headless 特徵）| curl 更安全 |

**關鍵發現**：
- **TravelPlus 價格資訊全部內嵌在靜態 HTML 中**：無需 JavaScript 渲染即可提取
- **無瀡覽器方法與瀏覽器自動化在價格提取上準確率一致**
- **成本優勢顯著**：curl 快 3-4 倍、無瀏覽器記憶體開銷
- **支持 CartRescue 採用「混合策略」**：瀏覽器用於結帳流程驗證，curl 用於價格監控

### 3. VIP 會員折扣計算測試（新場景）

**背景**：TravelPlus 產品頁面出現「[VIP價] : 若您為VIP會員,價格為定價88折,再享紅利加倍」。這引入了三層價格結構（定價 → VIP價 → 特價），測試模型能否正確計算。

**正確答案**（數學計算）：
- 原價（定價）：NT$13,800
- 特價：NT$8,080
- VIP會員價：13,800 × 0.88 = **NT$12,144**
- VIP會員價的等價折數：8.8折（原價的 88%）
- 實際折扣率（特價/原價）：8080/13800 = **58.55%**
- 等價折數（特價）：5.86折

**模型表現**：

#### Qwen2.5:7b（最優）
- 原價：NT$13,800 ✅
- 特價：NT$8,080 ✅
- VIP會員價：13,800 × 0.88 = **NT$12,144** ✅
- 實際折扣率：8080/13800 = **58.47%** ✅（實際 58.55%，誤差 < 0.1%）
- 等價折數：58.47% = **~5.85折** ✅
- VIP會員價等價折數：0.88 = **8.8折** ✅
- **完整正確理解三層價格結構**

#### Gemma3:4b（嚴重錯誤）
- 原價：NT$13,800 ✅
- 特價：NT$8,080 ✅
- VIP會員價：13,800 × 0.12 = **NT$1,656** ❌❌❌（錯誤理解「88折」為「扣除88%」而非「原價的88%」）
- 等價折數：計算為 42.76% ❌（錯誤公式）
- **根本性概念錯誤**：將「88折」理解為「12%折扣」，而非「原價的88%」

#### Llama3.2:3b（嚴重錯誤）
- 原價：NT$13,800 ✅
- 特價：NT$8,080 ⚠️（說反了：「特價NT:8080，意味著原價是NT$8,080」——這句本身沒邏輯）
- VIP會員價：8,080 × 0.88 = **NT$7,120.80** ❌（用特價而非定價計算）
- 實際折扣率：(8080-13800)/13800 = **-41.38%** ❌（公式錯誤，結果為負數）
- **多處概念混淆，完全不適合價格審計**

**三模型對比總結（VIP 場景）**：

| 模型 | 原價 | 特價 | VIP價 | 折扣率 | 等價折數 | 可信度 |
|------|------|------|-------|--------|---------|--------|
| **Qwen2.5:7b** | ✅ | ✅ | ✅ | ✅ | ✅ | **高** |
| **Gemma3:4b** | ✅ | ✅ | ❌ | ❌ | ❌ | **低** |
| **Llama3.2:3b** | ✅ | ⚠️ | ❌ | ❌ | ❌ | **極低** |

## 發現的問題或驚喜

### 🎉 重大驚喜

1. **TravelPlus 未部署 Bot 阻擋機制**：
   - 頁面完整載入（639KB）、產品頁可訪問（304KB）
   - 無 Cloudflare challenge、無 reCAPTCHA、無 Akamai 信號
   - CartRescue 目前可安全運行自動化測試

2. **無瀏覽器價格提取完全可行**：
   - `curl` + regex 與瀏覽器自動化提取結果完全一致
   - 速度快 3-4 倍、記憶體開銷更低
   - 支持「混合策略」：curl 監控價格、瀏覽器驗證結帳流程

3. **Qwen2.5:7b 連續第三天完美表現**：
   - VIP 三層價格結構（定價→VIP價→特價）全部正確計算
   - 是唯一正確理解「88折 = 原價的 88%」的本地模型

### ⚠️ 問題與限制

1. **Gemma3:4b 的「折扣」概念根本錯誤**：
   - 將「88折」理解為「扣除 88%」→ 計算 13,800 × 0.12 = 1,656
   - 這是中文電商語境下的致命錯誤
   - **結論**：Gemma3:4b 不適合用於任何涉及折扣計算的審計任務

2. **Llama3.2:3b 在多步驟計算中完全失控**：
   - VIP 價計算錯誤、折扣率為負數、等價折數無意義
   - 連續多日出現概念混淆，無改善跡象

3. **瀏覽器 headless 特徵暴露**：
   - `navigator.webdriver = True` 和 `HeadlessChrome` User-Agent
   - 雖然 TravelPlus 目前未檢測，但未來升級可能觸發阻擋
   - 生產環境需啟用 stealth 模式

## 文獻研究（新增 3 篇，累積 42 篇）

### arXiv:2609.01030 — Web Price Extraction: State of the Art and an Adaptive Browserless Implementation
- **與 CartRescue 相關性**：⭐⭐⭐⭐⭐
- **核心貢獻**：
  - 系統性比較四種價格提取方法：手動規則、瀏覽器自動化、無瀏覽器、ML/LLM
  - 提出結合 HTML 片段化 + 語法/語義/頻率規則 + 貝葉斯動態權重 + 遺傳演算法的混合系統
  - Precision 從 77.2% 提升至 **87.3%**，每頁處理時間降低 14%
- **與 CartRescue Day 18 直接對照**：
  - 本日測試證實 TravelPlus 的價格資訊全部內嵌在靜態 HTML 中，無需 JavaScript
  - 支持 CartRescue 採用「無瀏覽器優先」策略的可行性

### arXiv:2609.11152 — terms.txt: A Consent and Compensation Protocol for Agentic Web Access
- **與 CartRescue 相關性**：⭐⭐⭐⭐
- **核心貢獻**：
  - 提出 `terms.txt` 協議：機器人請求網站內容時需主動宣告身份、目的、付費意願
  - 基於 Web Bot Auth（RFC 9421 HTTP Message Signatures）+ HTTP 402 協商
  - 無依賴實現每請求僅增加 0.20–0.65 ms
- **與 CartRescue Day 18 直接對照**：
  - CartRescue 作為「審計機器人」，可主動採用 `terms.txt` 協議
  - 優勢：透明、可審計、減少被誤判為惡意爬蟲的風險

### Best Bot Detection 2026（產業評測）
- **與 CartRescue 相關性**：⭐⭐⭐⭐
- **核心貢獻**：
  - 評測 11 個 Bot 檢測工具、40 個評分標準、1400 萬請求
  - 測試對象：stealth headless Chrome、residential-proxy rotation、credential stuffing、browser-using AI agents
- **與 CartRescue Day 18 直接對照**：
  - CartRescue 目前的 headless Chrome 配置在標準 Bot 檢測下會被標記
  - 需配置 stealth 插件或 proxy 輪替以降低檢測率
