## 測試焦點：Day 18 計畫落實

### 1. Stealth 模式測試（瀏覽器指紋隱藏）

**背景**：Day 18 發現 `navigator.webdriver = True` 與 `HeadlessChrome` User-Agent 暴露。今日測試能否透過 JavaScript override 隱藏這些信號。

**測試結果**：

| 檢測項目 | 原始值 | Override 後 | 狀態 |
|---------|--------|-------------|------|
| `navigator.webdriver` | True | **False** | ✅ 成功覆寫 |
| User-Agent | HeadlessChrome/150 | 仍含 HeadlessChrome | ⚠️ 無法透過 JS 修改 |
| `chrome` object | `['loadTimes', 'csi', 'app']` | 不變 | ⚠️ 存在 |
| `plugins` | 5 | 不變 | ✅ 有值 |
| `languages` | `['zh-TW', 'zh', 'en-US', 'en']` | 不變 | ✅ 正常 |
| `platform` | Linux x86_64 | 不變 | ⚠️ 與常見 Windows 不同 |

**結論**：
- **`navigator.webdriver` 可透過 JS override 成功隱藏**：`Object.defineProperty` 有效
- **但 User-Agent 含 `HeadlessChrome` 無法僅透過 JS 修改**：需瀏覽器啟動參數 `--user-agent=...`
- **Playwright stealth 插件尚未安裝**：需額外安裝 `playwright-stealth` 或類似方案
- **風險評估**：TravelPlus 目前未檢測這些信號，但未來若升級 Bot Fight Mode，需啟用 stealth

### 2. 多網站泛化測試（無瀏覽器價格提取）

**背景**：Day 18 證實 TravelPlus 可用 `curl` + regex 提取價格。今日測試此方法能否泛化到 momoshop 與 PChome。

**測試結果**：

| 網站 | HTML 大小 | 價格提取 | 結果 |
|------|----------|---------|------|
| **TravelPlus** | 639KB | `curl` + regex | ✅ 成功（定價/會員價皆可提取）|
| **momoshop** | ~41KB（實際為 SPA shell）| `curl` + regex | ❌ 失敗（Next.js 動態渲染，HTML 無價格）|
| **PChome** | 142 bytes | `curl` + regex | ❌ **429 Too Many Requests**（被封鎖）|

**關鍵發現**：
- **TravelPlus 是傳統 ASP.NET 網站**：價格內嵌在靜態 HTML 中，curl 可直接提取
- **momoshop 是 Next.js SPA**：首頁載入後需 JavaScript 執行 API 請求才能取得價格，curl 無法取得
- **PChome 對 curl 直接返回 429**：有主動的 rate limiting / bot detection
- **結論**：「無瀏覽器優先」策略**僅適用於傳統 SSR 網站**，對 SPA 或嚴格防爬網站仍需瀏覽器自動化

### 3. VIP 折扣計算複測（新數據：AZPAC 行李箱）

**背景**：Day 18 用 NT$13,800 產品測試。今日換用實際提取的新數據（NT$12,800 定價 / NT$8,280 會員價），驗證模型是否穩定。

**正確答案**：
- 定價：NT$12,800
- 會員價：NT$8,280
- 實際折扣率：(12,800 - 8,280) / 12,800 = **35.31%**
- 等價折數：8,280 / 12,800 = **64.69% → 約 6.47 折**
- 若標示為「約6.4折」→ 實際 6.47 折，差異約 1.1% → **Low Risk**

**模型表現**：

#### Qwen2.5:7b（折數理解不穩定）
- 實際折扣率：35.28% ✅（誤差 < 0.1%）
- 等價折數：**3.53 折** ❌❌❌（嚴重錯誤：將「折數」理解為「1 - 折扣率」）
- 標示「約6.4折」判斷：「不正確，因為實際是 3.53 折」❌（連鎖錯誤）
- 風險評級：**High** ❌（錯誤比較折扣率與折數，得出 28.64% 差異）

**根本問題**：Qwen 對「折數」的理解不一致！
- Day 18（NT$13,800 產品）：正確計算 5.85 折、8.8 折
- Day 19（NT$12,800 產品）：錯誤計算為 3.53 折
- 同一模型、不同數據、不同結果

#### Gemma3:4b（部分正確但自我矛盾）
- 實際折扣率：35.36% ✅
- 等價折數：**64% → 約 6.4 折** ✅✅✅（正確！）
- 標示「約6.4折」：「是的，正確的」 ✅
- 風險評級：**High** ❌❌❌（自我矛盾！第 2 點說正確，第 4 點又說 High Risk）

**Gemma 第 4 點錯誤原因**：
- 計算差異 = |35.36% - 64%| = 28.64% > 20% → High
- 但這是錯誤的比較！它把「折扣率」和「折數」混為一談了

**重大發現**：
- **Qwen 和 Gemma 的「折數」理解都不穩定**
- **Qwen Day 18 正確、Day 19 錯誤**
- **Gemma 第 2 點正確、第 4 點又自我矛盾**
- **再次證實：必須使用規則引擎隔離計算，不能依賴 LLM**

## 發現的問題或驚喜

### 🎉 重大驚喜

1. **`navigator.webdriver` 可透過 JS 成功覆寫**：
   - `Object.defineProperty(navigator, 'webdriver', {get: () => false})` 有效
   - 為生產環境 stealth 配置提供可行路徑

2. **Gemma3:4b 在特定 prompt 下正確理解「折數」**：
   - 當 prompt 明確寫「如 6.4 折 = 64%」時，Gemma 第 2 點回答正確
   - 說明 prompt 設計對折扣語義理解有顯著影響

### ⚠️ 問題與限制

1. **Qwen2.5:7b 的「折數」理解不穩定**：
   - Day 18（NT$13,800 產品）：正確計算 5.85 折、8.8 折
   - Day 19（NT$12,800 產品）：錯誤計算為 3.53 折（把「折數」當成了「折扣率」）
   - **結論**：即使是最穩定的本地模型，折扣語義理解仍有波動

2. **Gemma3:4b 自我矛盾**：
   - 第 2 點正確說「約 6.4 折正確」
   - 第 4 點又說「差異 28.64% > 20% → High Risk」
   - **根本問題**：無法正確區分「折扣率」和「折數」兩個概念

3. **無瀏覽器方法無法泛化到 SPA 網站**：
   - momoshop（Next.js）：HTML 僅為 shell，價格需 JS 渲染
   - PChome：直接 429 封鎖 curl
   - **結論**：CartRescue 必須保留瀏覽器自動化作為 fallback
